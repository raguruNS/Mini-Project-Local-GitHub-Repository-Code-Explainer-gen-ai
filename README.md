# GitHub Repository Code Explainer (Local GenAI Mini Project)

Paste a GitHub URL → the app clones the repo, picks the relevant source files, feeds them to a
**locally running LLM**, and shows a beginner-friendly explanation. Nothing is hard-coded; the
explanation is generated by the model.

```
GitHub Repo → GitPython clone → file filtering/extraction → Local LLM → FastAPI → Streamlit
```

## Project structure
```
repo-explainer/
├── backend/
│   ├── main.py            # FastAPI app (/health, /explain)
│   ├── schemas.py         # Pydantic request/response models + URL validation
│   ├── repo_processor.py  # clone, filter files, prioritise, build context
│   ├── llm.py             # prompt + Ollama / Hugging Face inference
│   └── config.py          # model name, limits (env-overridable)
├── frontend/app.py        # Streamlit UI
├── requirements.txt
├── run_backend.sh / run_frontend.sh   (.bat versions for Windows)
└── README.md
```

## Setup
Prerequisites: Python 3.10+, Git installed, and [Ollama](https://ollama.com).

```bash
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt

ollama pull qwen2.5:3b            # small open-source model (~2 GB)
```

## Run (3 terminals)
```bash
ollama serve                                   # 1. local LLM (skip if already running)
uvicorn backend.main:app --port 8000           # 2. backend
streamlit run frontend/app.py                  # 3. frontend  -> http://localhost:8501
```
Open the Streamlit page, paste e.g. `https://github.com/pallets/flask`, click **Explain this repository**.

## Using Hugging Face Transformers instead of Ollama
```bash
export LLM_BACKEND=hf
export HF_MODEL=Qwen/Qwen2.5-1.5B-Instruct     # any small chat model (Phi, Gemma, Llama...)
uvicorn backend.main:app --port 8000
```
The model downloads once and then runs fully locally.

## Configuration (environment variables)
| Variable | Default | Meaning |
|---|---|---|
| LLM_BACKEND | ollama | `ollama` or `hf` |
| OLLAMA_MODEL | qwen2.5:3b | any model you pulled (`phi3`, `gemma2:2b`, `llama3.2:3b`) |
| CONTEXT_CHAR_BUDGET | 9000 | max characters of code sent to the LLM |
| MAX_NEW_TOKENS | 700 | max length of the explanation |

## How it works
1. **Validate** – Pydantic checks the URL is `https://github.com/user/repo`.
2. **Clone** – GitPython does a shallow (`depth=1`) clone into a temp folder (deleted afterwards).
3. **Select files** – skips `node_modules`, `venv`, lock files, binaries, huge files; keeps source code,
   README and config files (requirements.txt, package.json ...). README → config → entry points
   (`app.py`, `main.py`...) → other files, by priority.
4. **Build context** – folder tree + truncated file contents, capped by a character budget so small models don't overflow.
5. **LLM** – a prompt asks the local model for: Overview, Features, Technologies, How it works, Important files.
6. **Display** – FastAPI returns JSON; Streamlit renders the Markdown.

## Limitations
- Only a limited slice of large repos is analysed (small model context window); raise `CONTEXT_CHAR_BUDGET` for bigger models.
- Public repositories only (no authentication).
- Small models can make mistakes; the prompt tells them to use only the provided files.

## API
`POST /explain` `{"repo_url": "https://github.com/user/repo"}` →
`{explanation, languages, files_analyzed, model, repo_url}`. Interactive docs: http://localhost:8000/docs
